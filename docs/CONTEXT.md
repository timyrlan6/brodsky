# Контекст проекта «Бродский»

Дата начала: 2026-08-08. Этот файл — сводка решений и состояния для продолжения работы в новых сессиях. Краткая справка — `AGENTS.md`.

## 1. Задача (в терминах исследователя)
Изучить творчество Бродского: частотный анализ, поиск по словам, отсылки к слову в стихе. Пример исследовательского вопроса:
> Для Бродского важен символ «Угол». Он используется прямо («угол») и через похожие образы: «локоть», «колено», «конец пера», «мыс», «шпиль». Найти все вхождения, частоту, контексты, дистрибуцию по годам.

Это **семантическое поле / концепт-анализ**: ядро («угол») + периферия (слова с общим компонентом «острота/излом/граница»). Ядро поля задаётся **экспертно (вручную)**. В кластер входят и **многословные единицы** («конец пера»).

## 2. Продукт (видение)
Веб-приложение для чтения с семантическим слоем:
1. Пользователь читает стихотворение; слова-члены концепта (напр. «Угол») подсвечены.
2. **Интенсивность подсветки = величина символического значения**. На MVP = частота вхождений в корпус. В будущем — отдельный **граф зависимостей** (подменит источник метрики без изменения схемы).
3. Клик по слову → страница концепта: описание символа + все вхождения по всем томам (контекст + ссылка в стих).
4. Схема должна это поддерживать без переделки, когда появится граф.

## 3. Принятые решения
- **Стек**: .NET / C#; PostgreSQL (единственное хранилище); ASP.NET Core + веб-интерфейс; EF Core.
- **Форма приложения**: веб (не десктоп, не статика).
- **Величина символа**: пока по частоте; граф — отдельно, позже.
- **Описание символа**: LLM-черновик + ручные правки (в `concepts.description`).
- **Лемматизация MVP**: стеммер PostgreSQL (Snowball) + таблица исключений. Полный лемматизатор — позже.
- **UTF-8 выгрузки**: не нужны.
- **Корпус в контекст LLM не влезает** (~1,2–1,4 млн токенов, 4,88 млн символов чистого текста). LLM работает только на выборках из БД.

## 4. Роль LLM (границы)
| Можно | Нельзя |
|---|---|
| Расширение кластера (кандидаты в члены концепта) | Подсчёт частот (галлюцинирует — только SQL) |
| Классификация контекстов (буквально/образно/символ) | Bulk-лемматизация |
| Снятие омонимии (мыс=коса vs мысль) | Генерация цитат/отсылок (выдумывает) |
| Черновик описания символа | Изменение канонического текста |
| Аннотации к стихам | |

Архитектура: PostgreSQL (детерминированный слой) → выборки → LLM (семантический слой) → результат в БД → человек валидирует.

## 5. Данные
- `torrent/` — «Сочинения Иосифа Бродского» (2001–2003), 7 томов, fb2/epub/mobi. Файлы не изменяем (canonical).

- Разметка: `<section>` (дерево: часть → год/цикл), `<title><p>` (заголовок, внутри сноски `<a type="note">`), `<poem>`/`<stanza>`/`<v>`, `<subtitle>`. Безымянные стихи = `* * *`.
- Том 1: 219 `<poem>`, 1032 `<stanza>`, 7421 `<v>`. В томах есть проза (Нобелевская лекция) — для неё строки = абзацы.
- Омонимия и стеммер: «угол»→`угол`, но «угла/углу/углом/углы/углов»→`угл` — **не склеиваются**. «локоть»→`локт`✓, «колено»→`колен`✓, «мыс»→`мыс`✓, «шпиль»→`шпил`✓. Проверено в PostgreSQL (`to_tsvector('russian', …)`).

## 6. Схема БД `brodsky` (ревизия 2 — ревью продукта)
Текстовый слой:
```
volumes           (id, volume_no UNIQUE, title, year)
sections          (id, volume_id, parent_id NULL, title, sort_order)
works             (id, section_id, title NULL, subtitle, year, is_poem, source_ref, sort_order)
lines             (id, work_id, line_no, stanza_no NULL, text, UNIQUE(work_id, line_no))
words             (id, form UNIQUE, form_norm, stem)          -- form_norm: ё→е
word_occurrences  (id, word_id, work_id, line_id, char_start, char_end, position)
search_tsv        (work_id, tsv)  -- tsvector + GIN
```
Концептный слой:
```
concepts                  (id, slug UNIQUE, name, description, description_source, status)
concept_members           (id, concept_id, display_name, is_phrase, note)
concept_member_keys       (member_id, key_type, key_value, key_order)
                            -- key_type: 'stem' | 'form' | 'phrase'
concept_member_words      (member_id, word_id)   -- разрешённый список слов (авто + ручной)
concept_occurrences       (id, concept_id, member_id, work_id, line_id,
                            char_start, char_end, matched_text)  -- слова и фразы
concept_occurrence_notes  (concept_occurrence_id, is_symbolic, significance,
                            type, note, source, status)
```
Ключевые решения ревью-2 (матчинг концептов):
- **Вариант B (принято)**: источник истины для матчинга члена концепта — **явный список словоформ** (`concept_member_words`, ссылки на `word_id`), а НЕ стеммер. Snowball/`tsvector` — только генераторы кандидатов и пользовательский полнотекстовый поиск, не рантайм-истина концептов. Убирает дефекты Snowball (угол/угл: базовая форма не склеивается с косвенными — а именно в косвенных ~27 из 28 вхождений в т.1) и рассинхрон двух индексов.
- **Наполнение `concept_member_words`** — метод «кандидаты из корпуса → LLM-классификатор → SQL-сверка → человек»:
  1. кандидаты = реальные формы из `words` по близкому стему (ничего вне корпуса);
  2. LLM — **классификатор** («форма этого члена? / омоним / чужая лексема»), НЕ генератор форм;
  3. сверка: разрешённое множество ⊆ `words` (LLM не протащит несуществующее);
  4. человек утверждает; далее — истина, LLM не трогает.
  На MVP можно без LLM: SQL-кандидаты + ручная вычитка.
- **Два уровня, не смешивать**: (а) словоформа члена — морфология, детерминированно; (б) состав членов концепта — семантика (LLM+человек). Однокоренное типа «уголок» — НЕ форма «угла», а **кандидат в отдельный член** концепта «Угол» (со своей парадигмой).

Ключевые решения ревью:
- `word_occurrences` хранит **char-смещения** (для рендера подсветки), не только позицию токена.
- Заметки висят на **вхождении в концепт**, не на слове (слово может быть в нескольких концептах).
- Вес члена **вычисляется на лету** (`COUNT` по `concept_occurrences`), не хранится — граф подменит источник позже.
- Маппинг члена на слова расширяемый (`keys` + `member_words`): закрывает случай «угол/угл» и омонимы.
- Фразы («конец пера») поддержаны: `is_phrase`, span в `concept_occurrences`.

Индексы: `word_occurrences(word_id), (line_id), (work_id), (word_id, line_id)`; `concept_occurrences(concept_id, work_id), (member_id), (work_id)`; `lines(work_id, line_no)`; `works(section_id, sort_order)`; `words(stem)`; `concept_member_words(word_id)`; `search_tsv` GIN.

## 6a. Задача-максимум: собиратель образов Бродского

> Статус: **целевое видение** (не MVP). Концепция выработана и внутренне непротиворечива. Приоритеты этапов предварительны — «будем ещё рассуждать».

### Итог (что строим)

Не частотный словарь, а **реконструкция поэтической онтологии Бродского** из корпуса: система собирает образный ряд концепта из его строк, выжимает суть (квинтэссенцию), находит по ней новые вхождения — **под контролем человека на каждом шаге**. Всё трассируемо до `work_id`/`line_id`.

**Модель концепта (снизу вверх, от твёрдого к интерпретируемому):**
```
строки корпуса          ← детерминированно (SQL)
   ↓
ОБРАЗЫ (облако цитат)    сырьё: «мыс в море», «пик в воздухе», «конус»,
   ↓                     «нос корабля», «локоть в воздухе» — с привязкой к строкам
КВИНТЭССЕНЦИЯ            синтез сути: «нечто подобное мысу, вдающемуся в море:
   ↓                     острый пик, одним концом в воде, другим в суше»
                         — акт интерпретации высшего порядка, версионируемый текст
КАЧЕСТВА                конституенты квинтэссенции: {остриё, вдаётся в среду,
   ↓                     закреплён в основе} — извлечены ИЗ квинтэссенции
ПОЛЕ (члены)            всё, что резонирует с квинтэссенцией/качествами,
   ↓                     вероятностно: мыс, пик, локоть, перекрёсток, шпиль…
СВЯЗИ концептов         кресло = стул + перила(для локтя = угла тела)
```

**Как система работает — два раздельных РУЧНЫХ действия** (автономного цикла нет):
```
[Найти вхождения]        система: находит по смыслу кандидатов
                         человек: ✓подтверждает / ✗отклоняет → пополняется ПОЛЕ
                         (квинтэссенция при этом НЕ меняется)

[Обновить квинтэссенцию] человек: нажимает «обновить»
                         система: предлагает варианты
                         человек: редактирует, принимает → новая ВЕРСИЯ
```
Система НИКОГДА не меняет ни поле, ни квинтэссенцию сама. Связь поле↔квинтэссенция — только через человека. Версионирование делает дрейф видимым.

**Граф связей концептов** (мотивирующий кейс «кресло = стул + перила для угла тела»):
```
concept_relations (id, from_concept_id, to_concept_id, relation_type, source, status, note)
```
- `relation_type` — **фиксированный, но расширяемый** список: `is_a | has_part | for | function | opposes | …`
- `source`: `corpus | world | llm | inferred`; `status`: `hypothesis | confirmed`.
- Транзитивные цепочки («кресло → … → угол тела») помечаются как **вывод**, не факт; глубина ограничена.

**Три источника знания:**
| Источник | Роль | Пример | Статус |
|---|---|---|---|
| Корпус Бродского | основной, посылки-образы | «параллельные пересекаются на полюсе» | `override`/evidence |
| Знание о мире | фон, дефолт, достройка связей | подлокотник поддерживает локоть; параллельные не пересекаются | `default` |
| Интертекст | тексты-доноры (вносит человек) | образ мыса из другого поэта | **после программы-максимум** |

Приоритет: где Бродский высказался — **корпус перекрывает мир** (override). Пример: «параллельные линии пересекаются на полюсе» — ложно объективно, истинно в его поэтике.

### Обоснования ключевых решений (иммунитет от передумывания)

- **Истина — по Бродскому, мир как фон.** Цель — не объективная истина, а онтология автора. Мир — дефолт; где корпус говорит иное, приоритет у корпуса. Иначе система «исправит» Бродского и потеряет смысл.
- **Квинтэссенция обновляется только вручную, двумя раздельными действиями.** Автоцикл «квинтэссенция ⟲ находки ⟲ ищет по себе» даёт **дрейф** (концепт сползает, втягивает лишнее) и **самоподтверждение** (система находит то, что сама заложила). Разнесение «найти вхождения» и «обновить квинтэссенцию» + версионирование снимают это архитектурно.
- **Качество = собирательный образ из строк, а не канонический ярлык.** Суть системы — собирательность, а не точность формулировки. Смысл у поэта живёт в пучке образов, не в дефиниции. Единое качество, пока не потребуется разделить.
- **Различение качеств несёт всю строгость.** «Вдаётся» (мыс, локоть → угол) ≠ «окружён» (остров → не угол) — разные качества. Точность не абсолютна by design; неточность допустима, промпт LLM итеративно правится, человек валидирует.
- **LLM предлагает — человек решает, всегда.** LLM не считает частоты, не генерирует цитаты, не автономна. Извлечение образов/квинтэссенции — акт интерпретации; качество результата = качество эксперта-редактора.
- **Проверяемость смещается вверх по слоям** (образ → квинтэссенция → связи): чем выше, тем меньше SQL-детерминизма и больше экспертного суждения. Принято осознанно; трассировка до строк держит нижний слой твёрдым.

### Отвергнутые альтернативы (чтобы не ходить по кругу)

- **Матчинг словоформ через стеммер** → отвергнут. Snowball не склеивает «угол» с «угла/углу» (косвенные ~27 из 28 вхождений в т.1). Принят **вариант B**: явный список словоформ (`concept_member_words`) — истина; стеммер/`tsvector` — только кандидаты и пользовательский поиск.
- **Внешняя онтология (Wikidata/ConceptNet) как источник истины** → отвергнута. Навяжет объективную истину («меридианы не параллельны») и разрушит модель Бродского. Мир — только фон-дефолт, приоритет у корпуса.
- **Автоматический цикл обновления квинтэссенции** → отвергнут. Даёт дрейф и самоподтверждение. Только ручные действия.
- **Контролируемый словарь канонических качеств** → отвергнут. Собирательность образа важнее точности ярлыка; редукция к канону убивает живой смысл.
- **Дистрибутивная статистика как определитель поля** → понижена до вспомогательного «сигнала, где копать». Совстречаемость показывает *что* связано, но не *тип* связи и не отличает авторское от общеязыкового; поле определяют качества, не статистика.
- **Композиция примитивов сверху («Угол ⊗ Домен»)** → отвергнута как основной механизм. Качества индуцируются снизу из фактических образов корпуса (мыс/пик/конус → «остриё, вдаётся»), а не задаются априорной схемой.

### Осознанные риски
1. Малый корпус (7 томов) — статистика словами шумит; работать порогами/агрегацией.
2. Извлечение образов/квинтэссенции из поэзии — интерпретация уровня литературоведа; LLM даёт черновик.
3. Дрейф/самоподтверждение — снят архитектурно (два ручных действия + версии); опциональные страховки (seed/by-quality, anchors, негативы) — на потом.
4. Проверяемость смещается вверх — принято сознательно.
5. Гранулярность качеств — суть в собирательности; неточность допустима, промпт правится итеративно.
